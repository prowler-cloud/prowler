An emerging threat, such as a new vulnerability in an operating system image or a vendor appliance, is described to Prowler as a **threat signature**: data that says which machine images carry the vulnerability, how it is reached, and how to fix it. Detecting a threat needs no code. The `ec2_instance_emerging_threat_image`, `vm_emerging_threat_image`, and `compute_instance_emerging_threat_image` checks match every compute instance on AWS, Azure, and Google Cloud against every signature in force for the scan.

## Where Signatures Come From

| Source | Scope |
|--------|-------|
| `threat_signatures` in a provider's [configuration file](/user-guide/cli/tutorials/configuration_file) | Prowler CLI scans that use that configuration |
| Scan configuration in Prowler Cloud | Prowler Cloud scans of the providers that use that configuration |
| Prowler Cloud threat catalog | Every Prowler Cloud scan, maintained by Prowler as threats emerge |

Prowler SDK ships the matching engine and the checks, without signatures of its own. A signature in a scan configuration with the same `id` as one from the Prowler Cloud catalog replaces it for those scans.

## Writing a Signature

To detect a threat with Prowler CLI:

1. Copy `prowler/lib/threats/signatures/TEMPLATE.yaml.example`. The template explains each field, and `prowler/lib/threats/models.py` is the schema.
2. Add the signature as an item of the `threat_signatures` list under the provider in the configuration file.
3. Add `examples` to every image rule: real image names the rule must match and must miss, including the first fixed version of each release branch. A signature whose examples disagree with its rule is rejected.
4. Run the scan with the configuration file:

   ```console
   prowler aws --config-file config.yaml --checks ec2_instance_emerging_threat_image
   ```

## Writing Image Rules

Each signature lists one or more rules per cloud. An instance is affected when any rule for its cloud matches the image it was created from:

| Cloud | Name the rule matches | Publisher that proves provenance |
|-------|-----------------------|----------------------------------|
| AWS | Amazon Machine Image (AMI) name and description | AMI owner account ID |
| Azure | Gallery image definition, custom image name, or marketplace `offer-sku-version` | Marketplace publisher |
| Google Cloud | Boot disk source image name | Image project, for example `debian-cloud` |

Rules follow these principles:

- **Prefer publisher-verified matches.** List the official publisher. A match from a listed publisher proves the image; a name-only match is weaker evidence. Set `require_publisher: true` when the name alone is too generic to trust.
- **Capture the version.** A `(?P<version>...)` group in `name_regex` is compared against `versions`, a list of inclusive ranges. Write one range per release branch when fixes ship per branch, so patched point releases are not flagged. Dashes are read as dots, because Google Cloud image names cannot hold dots.
- **Exclude unaffected variants in the pattern.** For example, when only an image's minimal variant ships the vulnerable default, match that variant's name only.

## Describing Exposure and Impact

- **`exposure`** lists the protocol and every port the vulnerable service listens on. On AWS, the check reads the instance's own security groups and subnet. Omit `exposure` for a threat that is not reached over the network.
- **`credential_required`** is `false` for an authentication bypass or a pre-authentication remote code execution.
- **`mitigations`** lists the controls Prowler can observe that break the cyberattack chain: `password_authentication_disabled` and `port_not_exposed`.
- **`impact`** and **`remediation`** appear in the finding. State what a threat actor gains in one sentence, then how to contain the threat now and fix it.

## Limits

Signatures match the image an instance was created from. A host patched in place keeps its original image, so its finding stays failed until the host is replaced or the finding is muted with a reason. Threats in managed services, container images, or packages installed after launch are outside what image signatures can detect.
