title: 'Container Image Findings'
---

Prowler's container images are scanned with Trivy on every pull request and before publish. Builds fail on any CRITICAL finding that is not explicitly accepted in [`.trivyignore`](https://github.com/prowler-cloud/prowler/blob/master/.trivyignore), where every suppression carries a reason and an expiry date.

This page reports the findings that remain after that gate, and why each cannot be resolved by Prowler. It is written to be read alongside a scan report rather than to replace one.

Last reviewed: **2026-07-31**, Trivy 0.72.0.

## Current state

| Image | Critical | High |
|---|---:|---:|
| `prowler` (SDK) | 4 | 52 |
| `prowler-api` | 4 | 38 |
| `prowler-mcp` | 0 | 0 |
| `prowler-ui` | 0 | 0 |

`prowler-mcp` and `prowler-ui` carry no findings at either severity and require no suppressions.

## Critical findings

All four criticals are `perl-base`, on the SDK and API images only. They cannot be fixed:

1. **No fix exists.** Debian records one as `fix_deferred` and three as `affected`, none with a fixed version. A newer base image, `apt upgrade`, or a newer Debian release changes nothing.
2. **The package cannot be removed.** `perl-base` is Debian `Essential: yes`. Removing it requires `dpkg --force-remove-essential`, which also breaks `apt` for any image built downstream.
3. **Changing base distribution was evaluated and rejected.** Alpine removes perl entirely, but PowerShell publishes no `linux-musl-arm64` build in any release, so Microsoft 365 scanning would break on arm64. Wolfi keeps glibc and drops perl, but pinnable versioned tags require a paid subscription, so builds would not be reproducibly pinnable.

They are also not reachable. Trivy attributes `src:perl` CVEs across every binary package built from it, so `perl-base` is flagged for modules that only `perl-modules-*` ships, and neither image installs those. Nothing in either image invokes perl — verified by sweeping for perl shebangs, shell and Python callers of `perl`, ELF binaries containing the string, and `.pl`/`.pm` files or perl subprocess calls anywhere in site-packages.

## High findings

The 52 remaining on the SDK fall into four groups. None is fixable by Prowler.

### Debian packages with no upstream fix (35)

Every one is reported by Trivy as having no fixed version. The affected packages are `libcurl4t64` (7), `perl-base` (4), `wget` (2), the `gnupg` suite (`gnupg`, `gpg`, `gpg-agent`, `gpgconf`, `gpgsm`, `dirmngr`, `gnupg-l10n`), the `util-linux` family (`util-linux`, `mount`, `libmount1`, `libblkid1`, `libuuid1`, `libsmartcols1`, `bsdutils`, `login`, `liblastlog2-2`), `ncurses` (`ncurses-base`, `ncurses-bin`, `libncursesw6`, `libtinfo6`), `gzip` and `libacl1`.

Debian has not released patched versions. These resolve when Debian ships fixes, and the images pick them up on the next base rebuild.

### Components declared in vendored SBOMs (9)

PowerShell's `MicrosoftTeams` module ships its own SPDX manifest listing the components Microsoft used to build it. Trivy parses that manifest and reports its contents as if they were installed packages.

They are not Prowler dependencies, and only Microsoft can change them by rebuilding the module. The module is already at 7.9.0, the newest version `Install-Module` resolves.

### Scanner artifacts (4)

Four findings refer to packages that are not present in the image at all:

| Reported | Reality |
|---|---|
| `setuptools` 70.3.0 | The virtual environment contains **82.0.1**, well beyond the 78.1.1 fix |
| `msgpack` 1.1.2 | Not installed — `importlib.util.find_spec` returns nothing |
| `fast-uri` 3.1.2 (×2) | An npm entry inside the MicrosoftTeams SBOM; no Node.js runtime or `node_modules` exists in the image |

These are reporting artifacts from stale vendored SBOM metadata, not accepted risk.

### Bundled Trivy binary (4)

The SDK image ships Trivy for infrastructure-as-code scanning. Four findings are in its own Go dependencies (`golang.org/x/text`, `google.golang.org/grpc`, `oras.land/oras-go`, `containerd`). Prowler pins the newest release, 0.72.0; the fixes require versions Trivy has not yet shipped. They clear on the next Trivy release.

## What was fixed

The 2026-07-31 review resolved every finding that had an available fix:

| Change | Effect |
|---|---|
| PowerShell 7.5.0 → 7.5.9 | .NET assembly CVEs in `pwsh.deps.json` |
| Trivy 0.71.2 → 0.72.0 | containerd, `x/text`, gRPC and oras in the bundled binary |
| uv 0.11.14 → 0.12.0 | `quinn-proto` in `uv` and `uvx` |
| `joserfc` 1.6.5 → 1.6.8 | SDK dependency |
| `fastmcp` 3.4.4 → 3.4.5, plus pins on `cryptography` 48.0.1, `joserfc` 1.6.8, `mcp` 1.28.1 and `python-multipart` 0.0.30 | all 7 findings on `prowler-mcp` |

## Reducing the remainder

The largest group — Debian packages — is bounded by what the runtime image installs. The SDK and API images currently use their build stage as the runtime stage, so build-only packages such as `build-essential`, `pkg-config`, `libzstd-dev` and `zlib1g-dev` remain in the shipped image along with everything they pull in. Splitting the runtime into a separate stage would remove those packages, and their findings with them, rather than waiting for Debian to patch them.
